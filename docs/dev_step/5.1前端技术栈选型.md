# 5.1 前端技术栈选型（面向 AI 协同开发）

## 1. 目标与约束
- 当前后端为 Python + FastAPI，接口已具备可调用能力。
- 前端团队当前开发经验较弱，需要“低门槛 + 高可维护 + AI 生成质量稳定”的方案。
- 需要支持后续页面：项目、数据集、任务列表、任务详情、指标/日志、LLM 报告、A/B/C 候选实验。

## 2. 推荐技术栈（结论）
- 框架：Next.js 14（App Router）
- 语言：TypeScript（严格模式）
- UI：Tailwind CSS + shadcn/ui
- 数据请求：TanStack Query
- 表单与校验：React Hook Form + Zod
- 图表：ECharts（`echarts-for-react`）
- 质量保障：ESLint + Prettier + Vitest + Playwright
- 包管理：pnpm
- API 对接：OpenAPI（FastAPI `/openapi.json`）+ 代码生成客户端

## 3. 为什么这个栈最适合“AI + 新手”
- Next.js 目录约定清晰，AI 生成页面结构更稳定。
- TypeScript 能在开发期发现大量错误，降低“看不懂但能跑”的风险。
- shadcn/ui 是“可复制源码”组件，便于 AI 定制，不受黑盒库限制。
- TanStack Query 能把“加载/错误/缓存/重试”标准化，AI 更容易复用模式。
- Zod 可将后端契约转成前端运行时校验，减少联调口径偏差。
- Playwright 适合写“业务流程冒烟”，让不会开发的人也能验证“能不能用”。

## 4. 与现有后端的对齐方式
- 运行方式：前后端分离开发（前端 `3000`，后端 `8000`）。
- 联调策略：前端统一使用 `NEXT_PUBLIC_API_BASE_URL` 指向 FastAPI。
- 契约来源：以 FastAPI OpenAPI 文档为准，前端请求类型从 OpenAPI 生成。
- 错误处理：统一适配后端结构：
  - 成功：`{ ok: true, data: ... }`
  - 失败：`{ ok: false, error: { code, message, details, type } }`

## 6. 不推荐方案（当前阶段）
- 不推荐 Vue + Element Plus：虽然上手快，但与当前代码/文档沉淀方向不一致。
- 不推荐纯 JS：缺少类型约束，AI 生成代码后期维护成本高。
- 不推荐过早引入微前端：当前是 MVP 阶段，复杂度收益比低。

## 7. 版本建议
- Node.js: 20 LTS
- pnpm: 9+
- Next.js: 14+
- React: 18+
- TypeScript: 5+

## 8. 验收口径
- 首屏可访问，核心页面可导航。
- 页面能完成“查、提、看”基础交互（查询、提交、查看）。
- 所有接口调用统一走 API Client 层，无页面内裸 `fetch`。
- 至少 5 条 Playwright 冒烟用例覆盖关键流程。
