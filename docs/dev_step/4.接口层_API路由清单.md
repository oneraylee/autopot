# 4.接口层 API 路由清单

## 1. 说明
- Web 框架：FastAPI
- 应用入口：`src/web/app.py`
- 路由定义：`src/web/routes.py`
- 业务适配层：`src/api/*_routes.py`
- 联调用例：`docs/dev_step/4.接口层_API联调用例.md`
- 知识库接口设计：`docs/updates/20260323_知识库/1.知识库架构设计.md`（§ 11）

统一响应结构：
- 成功：`{"ok": true, "data": {...}}`
- 失败：`{"ok": false, "error": {"code": "...", "message": "...", "details": [], "type": "..."}}`

统一状态码映射（`src/web/routes.py`）：
- `NOT_FOUND -> 404`
- `CONFLICT -> 409`
- `SYSTEM_ERROR -> 500`
- 其他错误默认 `400`

## 2. 健康检查

| 方法 | 路径 | 说明 | 适配层方法 |
|---|---|---|---|
| GET | `/health` | 服务健康状态 | 无（直接返回） |

## 3. 项目与 KPI 配置

| 方法 | 路径 | 说明 | 适配层方法 |
|---|---|---|---|
| GET | `/projects/{project_id}/kpi-config` | 查询项目 KPI 配置 | `ProjectRoutes.get_project_kpi_config` |
| PUT | `/projects/{project_id}/kpi-config` | 更新项目 KPI 配置 | `ProjectRoutes.put_project_kpi_config` |

PUT 请求体关键字段：
- `primary_kpi: str`
- `threshold: number`
- `weights.eval: number`
- `weights.deploy: number`
- `deploy_constraints[]: {metric, operator, value}`

## 4. 数据集与场景标签

| 方法 | 路径 | 说明 | 适配层方法 |
|---|---|---|---|
| POST | `/datasets/{dataset_id}/versions/import` | 导入数据集版本 | `DatasetRoutes.import_dataset_version` |
| POST | `/datasets/{dataset_id}/versions/{version}/freeze` | 冻结数据集版本 | `DatasetRoutes.freeze_dataset_version` |
| PUT | `/datasets/versions/{dataset_version_id}/scene-labels` | 批量写入/更新场景标签 | `DatasetRoutes.upsert_scene_labels` |
| GET | `/datasets/versions/{dataset_version_id}/scene-coverage` | 查询场景覆盖率统计 | `DatasetRoutes.get_scene_coverage` |

- 覆盖率查询参数：`dimensions`（可多值）

## 5. 任务编排与观测

| 方法 | 路径 | 说明 | 适配层方法 |
|---|---|---|---|
| POST | `/jobs` | 创建训练任务 | `JobRoutes.create_job` |
| GET | `/jobs/{job_id}` | 查询任务状态 | `JobRoutes.get_job` |
| POST | `/jobs/{job_id}/start` | 启动任务并绑定 GPU | `JobRoutes.start_job` |
| POST | `/jobs/{job_id}/logs` | 追加任务日志 | `JobRoutes.append_log` |
| GET | `/jobs/{job_id}/logs` | 分页查询日志 | `JobRoutes.get_logs` |
| POST | `/jobs/{job_id}/metrics` | 写入指标点 | `JobRoutes.record_metric` |
| GET | `/jobs/{job_id}/metrics` | 按时间窗口查询指标 | `JobRoutes.get_metrics` |

请求要点：
- 创建任务体需包含 `resources.gpu_count > 0`
- 日志分页参数：`page`, `page_size`
- 指标窗口参数：`start_ts`, `end_ts`

## 7. Proposal 工作流

| 方法 | 路径 | 说明 | 适配层方法 |
|---|---|---|---|
| POST | `/proposals/validate` | 校验候选实验 | `ProposalRoutes.validate_proposals` |

## 9. 知识系统

| 方法 | 路径 | 说明 | 适配层方法 |
|---|---|---|---|
| POST | `/knowledge/sources` | 注册知识源 | `KnowledgeRoutes.create_source` |
| GET | `/knowledge/sources` | 查询知识源列表 | `KnowledgeRoutes.list_sources` |
| POST | `/knowledge/documents/import` | 导入文档 | `KnowledgeRoutes.import_document` |
| GET | `/knowledge/documents/{document_id}` | 查询文档状态 | `KnowledgeRoutes.get_document` |
| GET | `/knowledge/documents/{document_id}/chunks` | 查询切片结果 | `KnowledgeRoutes.get_chunks` |
| POST | `/knowledge/techniques/extract` | 从文档自动抽取候选技能 | `KnowledgeRoutes.extract_techniques` |
| POST | `/knowledge/techniques` | 创建或确认技能条目 | `KnowledgeRoutes.create_technique` |
| PUT | `/knowledge/techniques/{technique_id}` | 更新技能定义 | `KnowledgeRoutes.update_technique` |
| GET | `/knowledge/techniques` | 按条件查询技能列表 | `KnowledgeRoutes.list_techniques` |
| GET | `/knowledge/techniques/{technique_id}` | 获取技能详情 | `KnowledgeRoutes.get_technique` |
| GET | `/knowledge/techniques/{technique_id}/relations` | 获取技能关系图 | `KnowledgeRoutes.get_technique_relations` |
| POST | `/knowledge/techniques/{technique_id}/publish` | 发布技能 | `KnowledgeRoutes.publish_technique` |
| POST | `/knowledge/retrieval/search` | 基于 QuerySignature 检索候选技能 | `KnowledgeRoutes.search` |
| POST | `/knowledge/retrieval/resolve-conflicts` | 对候选技能做冲突消解 | `KnowledgeRoutes.resolve_conflicts` |
| POST | `/knowledge/retrieval/compose-context` | 生成送给 Agent 的最小知识上下文 | `KnowledgeRoutes.compose_context` |
| POST | `/knowledge/outcomes` | 记录技能在实验中的实际效果 | `KnowledgeRoutes.record_outcome` |

请求要点：
- 技能查询参数：`task_type`, `category`, `layer`, `maturity`, `evidence_level`, `status`
- 检索请求体需包含 `query_signature`（task_type, model_family, 等）
- 冲突消解请求体：`technique_ids` + `constraints`
- 上下文组装请求体：`planning_type` + `query_signature` + `top_k`

## 10. LLM Gateway 管理
