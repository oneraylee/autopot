## 2. TDD Implementation Steps（TDD 执行步骤）
- **Step 0.1: 建立模块依赖拓扑与开发边界**
  - `Task`: 固化 Bottom-Up 顺序与各层 DoD（Definition of Done）。
  - `Test File`: `tests/architecture/test_dev_topology_contract.py`
  - `Impl File`: `docs/dev_step/0.总览.md`
  - `Checklist`:
    - [ ] 编写失败的单元测试 (Red)
    - [ ] 实现最小代码通过测试 (Green)
    - [ ] 统一命名与依赖描述，消除歧义 (Refactor)

- **Step 0.2: 约束跨层依赖规则**
  - `Task`: 明确“上层可依赖下层，下层不可反向依赖上层”的规则并形成可检查清单。
  - `Test File`: `tests/architecture/test_layer_dependency_rules.py`
  - `Impl File`: `docs/dev_step/0.总览.md`
  - `Checklist`:
    - [ ] 编写失败的单元测试 (Red)
    - [ ] 实现最小代码通过测试 (Green)
    - [ ] 合并重复规则并补齐示例 (Refactor)

- **Step 0.3: 定义阶段验收入口**
  - `Task`: 为 Common/数据层/业务层/接口层定义阶段性验收命令与产出清单。
  - `Test File`: `tests/acceptance/test_phase_exit_criteria.py`
  - `Impl File`: `docs/dev_step/0.总览.md`
  - `Checklist`:
    - [ ] 编写失败的单元测试 (Red)
    - [ ] 实现最小代码通过测试 (Green)
    - [ ] 对齐交付清单字段命名 (Refactor)

## 3. Verification（验证标准）
- 开发顺序固定为：`Common库 -> 数据层 -> 业务逻辑层 -> 接口层`。
- 每层均具备可独立执行的最小测试集合，且不依赖更上层代码。
- 每层均有明确 DoD：测试通过、接口契约稳定、关键错误码可观测。
