# Common库 Phase 1 开发计划（领域枚举与错误码）

## 项目概述

本阶段建立 Common 层最小可复用语义基线：统一任务状态、任务类型、精度模式与错误码，消除后续层重复定义与命名漂移。

**架构设计原则**:
- 单一事实源 - 枚举与错误码只在 `src/common/domain_types.py` 定义
- 类型先行 - 先定义类型契约，再对接实现层
- 可扩展兼容 - 预留多 Runner、多导出后端、多失败原因扩展

## 架构验收标准

### 分层与复用
- [ ] 业务层/数据层/接口层均从 Common 导入，不再重复定义同语义枚举
- [ ] 错误码支持训练、评估、LLM、导出链路主故障分类

### 一致性
- [ ] 枚举值命名与系统状态机语义一致（CREATED/QUEUED/RUNNING/...）
- [ ] 错误码与附录建议集合对齐（TRAIN_OOM/EVAL_FAILED/LLM_FAILED 等）
