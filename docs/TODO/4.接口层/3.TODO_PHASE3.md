# 接口层 Phase 3 开发计划（候选实验校验与一键建任务 + 导出/部署基准 API）

## 项目概述

本阶段完成接口层高价值闭环：候选实验 A/B/C 校验、用户确认后一键创建训练任务，以及导出任务与部署基准查询接口，支撑 M2/M3 目标并形成可审计实验迭代流程。

**架构设计原则**:
- 人在回路 - 候选实验默认不自动执行，必须用户确认后创建任务
- 审计优先 - 关键动作必须记录 `who/when/baseline_job_id`
- 扩展兼容 - 导出后端参数校验抽象化，便于未来扩展多后端

## 开发步骤与测试用例

| 子任务 | 输入 | 输出 | 依赖 | 测试用例 |
|---|---|---|---|---|
| P3-1 定义 Proposal 工作流 API 契约 | NextExperiments 规范 + 用户确认策略 | `POST validate_proposals`、`POST create_from_proposal` | Proposal 服务 | 缺失 `evidence_refs` 拒绝；未经确认禁止创建任务；baseline_job_id 必填 |
| P3-2 实现候选实验校验接口 | P3-1 契约 | `src/api/proposal_routes.py` 校验路由 | Schema 校验器 + 资源校验器 | 参数非法、资源不足、阈值冲突分别返回稳定错误码 |
| P3-3 实现用户确认后一键建任务接口 | 人在回路要求 | Proposal→Job 创建路由 | Job Service | 确认后成功创建新 job；重复提交幂等；审计字段写入完整 |
| P3-4 增强审计字段一致性 | Step 4.5 Refactor 要求 | 审计字段标准结构 | P3-1~P3-3 | 响应体、审计日志、持久化记录字段同名同义 |
| P3-5 定义导出与部署基准 API 契约 | PRD 导出需求 | `POST /exports`、`GET /exports/{id}`、`GET /jobs/{id}/deploy_benchmark` | Export Service | 不支持 backend 拒绝；任务未完成训练时禁止导出 |
| P3-6 实现导出任务与基准查询接口 | P3-5 契约 | `src/api/export_routes.py` | Export 服务 + Artifact 服务 | 导出状态轮询可用；基准 JSON 契约校验；导出失败映射 `EXPORT_FAILED` |
| P3-7 抽象后端参数校验器 | Step 4.6 Refactor 要求 | 可复用 backend validator | P3-5~P3-6 | TensorRT 参数校验通过；未知后端拒绝；参数缺失错误可诊断 |
