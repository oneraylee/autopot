# 数据层 Phase 1 开发计划（项目/KPI 与数据集版本仓储）

## 项目概述

本阶段建立数据层最小闭环：完成 `Project`、`ProjectKpiConfig`、`Dataset`、`DatasetVersion` 的仓储能力与版本冻结约束，为训练任务与评估链路提供可追溯元数据基线。

**架构设计原则**:
- 元数据一致性优先 - 统一仓储返回模型，避免跨层重复拼装
- 版本不可变 - 冻结后的 `DatasetVersion` 禁止破坏性修改
- 可追溯审计 - KPI 配置与数据版本变更需具备版本化读取能力

## 架构验收标准

### 分层设计
- [ ] 业务层仅通过 repository 访问 `Project/KPI/DatasetVersion` 元数据，不直接依赖底层存储细节
- [ ] repository 对外返回统一领域模型，避免返回裸字典造成契约漂移

### 核心组件
- [ ] `ProjectRepository` 支持项目与 KPI 配置读写、按版本查询
- [ ] `DatasetRepository` 支持数据集与数据集版本创建、冻结、查询

### 统一接口
- [ ] 关键查询接口具备稳定入参与错误语义（不存在、冻结冲突、参数非法）
- [ ] 冻结约束与附录/PRD 的“可复现”要求一致
