# 业务逻辑层 Phase 2 开发计划（评估与证据闭环：EvalService + EvidencePackBuilder + AgentService）

## 项目概述

本阶段在训练完成后建立“评估 → 证据包 → Agent 建议”的自动化闭环，确保评估输出可校验、建议可审计、默认不自动建任务，并且每条建议都可追溯到证据字段。

**架构设计原则**:
- 契约驱动 - 评估结果、证据包、候选实验均先校验再流转
- 审计优先 - 所有建议必须附带 evidence 引用路径
- 安全默认 - Agent 仅生成候选，不直接触发训练任务创建

## 架构验收标准

### 分层设计
- [ ] `EvalService`/`EvidencePackBuilderService`/`AgentService` 仅通过受控接口交互，不直连 UI 层
- [ ] 证据组装与 LLM 调用解耦，便于替换 Agent/Prompt 策略

### 核心组件
- [ ] `EvalService` 支持脚本执行、JSON contract 校验、失败日志落盘
- [ ] `EvidencePackBuilderService` 支持多源聚合与大文件索引化输出
- [ ] `AgentService` 支持分析报告与 A/B/C 候选实验校验

### 统一接口
- [ ] 输出结构与 `EvalReport` / `EvidencePack` / `NextExperiments` 契约一致
- [ ] `next_experiments.json` 缺失 `evidence_refs` 或非法变更时拒绝通过

| 子任务 | 输入 | 输出 | 依赖 | 测试用例 |
|---|---|---|---|---|
| P2-1 实现评估脚本执行器 | 评估脚本入口规范 | `EvalService.run_evaluation` | Phase 1 | 脚本成功返回结果路径；退出码非0时标记 EVAL_FAILED |
