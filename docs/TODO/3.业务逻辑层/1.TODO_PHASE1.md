# 业务逻辑层 Phase 1 开发计划（训练执行主链路：DatasetService + JobService + RunnerAdapter）

## 项目概述

本阶段构建业务逻辑层最小可运行闭环：从数据统计与质量检查出发，完成训练任务创建/排队/状态流转与 GPU 资源锁，再通过 LocalRunner 适配器启动训练并回传运行结果。

**架构设计原则**:
- 服务编排优先 - 业务服务负责流程编排，仓储负责持久化
- 状态机强约束 - 仅允许系统架构定义的合法状态迁移
- 执行抽象隔离 - Runner 细节封装在 Adapter 内，业务层只消费统一结果

## 架构验收标准

### 分层设计
- [ ] `DatasetService`/`JobService`/`RunnerAdapter` 仅依赖 repository 与 common 契约，不直接耦合接口层
- [ ] 训练流程入口由 `JobService` 统一编排，不在多个服务中分散状态迁移逻辑

### 核心组件
- [ ] `DatasetService` 完成类别分布、空图比例、尺寸分布、场景覆盖率统计能力
- [ ] `JobService` 完成 Job 创建、排队、状态流转、GPU 分配与回收
- [ ] `LocalRunnerAdapter` 完成容器参数构建、挂载/环境注入、执行结果标准化

### 统一接口
- [ ] 服务间传递统一 DTO（JobSpec/RunnerResult/DatasetReport）
- [ ] 运行失败统一映射错误码（如 TRAIN_OOM、TRAIN_NAN、DATA_INVALID）

## 开发步骤与测试用例

| 子任务 | 输入 | 输出 | 依赖 | 测试用例 |
|---|---|---|---|---|
| P1-1 实现数据统计聚合入口 | 数据层统计仓储 + PRD 统计需求 | `DatasetService.get_dataset_report` | 数据层 Phase1/2 | 类别分布正确；空图比例计算正确；场景覆盖率组合统计正确 |
| P1-2 实现任务创建与排队编排 | JobSpec 约束 + 状态机定义 | `JobService.create_and_queue_job` | P1-1 + 数据层 Phase3 | CREATED→QUEUED 合法；非法初始参数拒绝；dataset_version 未冻结时阻断 |
| P1-3 实现运行中状态迁移与资源锁 | GPU lock 需求 + 资源仓储 | `JobService.start_job/finish_job/fail_job` | P1-2 | GPU 分配冲突阻断；RUNNING→SUCCEEDED/FAILED 正确；资源回收幂等 |
| P1-4 实现 LocalRunner 参数构建 | 模块设计 Runner 注入约束 | `LocalRunnerAdapter.build_run_command` | P1-2 | CUDA_VISIBLE_DEVICES 注入正确；挂载路径正确；train_args 透传完整 |
| P1-5 实现执行结果标准化与错误映射 | 附录错误码建议 | `LocalRunnerAdapter.run` 标准结果 | P1-4 | OOM/NaN/退出码映射稳定；stdout/stderr 可追溯；异常不吞没 |
| P1-6 统一训练主链路编排 | 上述服务能力 | `JobService.dispatch_to_runner` | P1-3/P1-5 | 创建任务到启动训练端到端通过；失败时状态与错误码一致 |
