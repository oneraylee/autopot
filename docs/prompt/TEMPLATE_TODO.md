## 使用说明

### 🔄 动态阶段拆分指南

#### 何时需要拆分阶段？
**数量指标**:
- 核心功能步骤 > 5个
- 高级特性步骤 > 4个
- 单个阶段开发时间 > 4周
- 阶段内功能复杂度 > 中等

**复杂度指标**:
- 包含多个技术领域（API + 数据库 + 缓存 + 消息队列）
- 涉及多个业务域（用户管理 + 订单处理 + 支付结算）
- 需要不同专业技能（前端 + 后端 + DevOps + 数据工程师）

**团队协作指标**:
- 团队成员 > 3人
- 需要并行开发以提高效率
- 不同团队负责不同功能模块

#### 如何智能拆分？

**按技术栈拆分**:
```
原架构: 基础 → 核心功能 → 高级特性
拆分后: 基础 → 数据层 → 服务层 → API层 → 集成层 → 优化层
```

**按业务价值拆分**:
```
原架构: 基础 → 核心功能 → 高级特性
拆分后: 基础 → MVP功能 → 增强功能 → 扩展功能 → 创新功能
```

**按依赖关系拆分**:
```
原架构: 基础 → 核心功能 → 高级特性
拆分后: 基础 → 独立功能A → 独立功能B → 集成功能 → 优化功能
```

**按基础设施层次拆分** (新增):
```
原架构: 基础架构 (阶段1) → 核心功能 → 高级特性
拆分后: 基础设施 → 数据基础 → 服务基础 → 接口基础 → 核心功能 → 高级特性
```

**按团队专业拆分** (新增):
```
原架构: 基础架构 → 核心功能 → 高级特性
拆分后: DevOps基础设施 → 后端数据层 → 后端服务层 → 前端接口层 → 全栈功能 → 优化部署
```
